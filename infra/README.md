# Local infrastructure

The base Compose stack runs MySQL, Redis, Kafka, three Java services and the dashboard. Start with `./scripts/dev-up.ps1`; `-Observability` also enables Prometheus, Grafana, Loki, Tempo and the OpenTelemetry Collector. Bash uses `bash scripts/dev-up.sh --observability`. The startup scripts use dependency health checks and `compose up --wait`. Docker Desktop should have roughly 6 GB available for core, 8 GB for observability; these are planning estimates, not measured minimums. Java heap/container limits avoid consuming all laptop RAM, and telemetry retains 24 hours. Building images may require additional memory.

Tempo now has a 1 GiB container limit and `GOMEMLIMIT=800MiB`. The 2026-10-01 audit reproduced an OOM kill at the former 384 MiB limit while replaying existing WAL and completing Parquet blocks. After backing up the stopped volume and increasing the budget, the same volume started and a real API-to-worker trace was retrieved. No WAL/volume reset was used. Existing incomplete WAL metadata also produced a recovery warning; this verification does not establish completeness of historical traces. See the [publication audit](../docs/PUBLICATION_AUDIT_2026-10-01.md).

All published ports bind to localhost. Database/cache/broker ports stay internal. There is no production authentication/TLS inside the demo network. `.env.example` contains local-only defaults; copy to ignored `.env`. MySQL uses three databases with one local user; production should grant a separate identity per service. Database initialization runs once per named volume. Changing credentials in `.env` does not alter an already-initialized database. `dev-down` preserves data; `docker compose down -v` explicitly deletes it.

The single-node Kafka broker uses KRaft, one replica and no quorum fault tolerance. Applications create only their required topics. Redis has a 96 MB cache bound and LRU eviction; it is deliberately non-durable. Java runs as an unprivileged user. Pinned image versions improve reproducibility; updating dependencies requires re-running CI and a complete demo, and tags are not equivalent to immutable image digests.

OpenTelemetry Java agent 2.20.0 is downloaded during image build with a pinned SHA-256 (`191666bf4346ab0677f92304bb272cd85f5954f49c03bb9636134e59c9a3276d`). It instruments HTTP, JDBC, Redis and Kafka without coupling the domain code to an exporter. Traces/logs flow via OTLP to the Collector and then Tempo/Loki. Micrometer metrics are scraped directly by Prometheus, avoiding duplicate metric streams. OTel is disabled in core mode; enabling the profile alone does not enable the agent unless `OTEL_SDK_DISABLED=false`, which `dev-up -Observability` sets automatically.

Grafana provisions all three data sources and the IncidentLens dashboard. Log data uses Loki's [native OTLP ingestion](https://grafana.com/docs/loki/latest/send-data/otel/) with schema v13 and structured metadata. The collector does not mount the Docker socket. Trace sampling is 100% for this low-volume lab; production requires a sampling and retention policy. The agent's [release](https://github.com/open-telemetry/opentelemetry-java-instrumentation/releases/tag/v2.20.0) is fixed independently of the application.

Grafana and Prometheus have HTTP readiness probes. Grafana's first durable SQLite migration can take several minutes; its optional plugin preinstall is disabled because the supplied dashboard only needs bundled data sources. `node scripts/verify-observability.mjs` verifies actual data paths after a workload, including a trace shared by the API and worker. The [executed proof](../docs/results/observability/verification.json) and [final database reconciliation](../docs/results/final-consistency.json) distinguish configuration checks from observed runtime behavior. The dashboard's workload throughput/error queries explicitly select demo-api so control-plane reads do not dilute the results.

Fault-control access is intentionally local. Do not expose the control API publicly. OpenAI-compatible RCA is optional: configure `RCA_BASE_URL`, `RCA_API_KEY`, `RCA_MODEL` in `.env` only after deciding which evidence may leave your machine. No API key is needed for the default deterministic analysis.
